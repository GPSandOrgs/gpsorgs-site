GPS & Orgs Community site (gpsorgs.com). Static HTML, one shared stylesheet in assets/site.css, no build step. Repository: github.com/GPSandOrgs/gpsorgs-site (public, owned by the GPSandOrgs organization). Committee members edit through pull requests; organization owners can push to main directly. Deployed by Cloudflare Pages from this repo: build command empty, output directory `/`. Pages are generated by `gen.py` (edit the page bodies there, run `python3 gen.py`, commit the HTML).

Readings: the reference list lives in `READINGS_SHELVES` in `gen.py` and is the master copy — add new references there and re-run `gen.py`. Each shelf runs newest first, alphabetical within a year, and every entry gets a Google Scholar link generated from its title. The `readings-archive` branch is a leftover from the launch, when the public page carried the headings only and that branch held the references; the public page now carries them, so the branch can be deleted.

Pages: index, committee, members (registry, being built), events, resources (community noticeboard), readings, teaching (placeholder), join (mailing list), register (being built), contact. Navigation groups Members / Resources / Join are native <details> dropdowns; a small script in the page footer closes one when another opens and assembles the hello@ address so it is not in the page source.

Member registry (v2): pages under `/members`, `/register` and `/api/members/*` are Cloudflare Pages Functions; shared code in `lib/` (`shell.js` is generated by gen.py from the same page template as the static pages, `members.js` holds sessions, codes and forms). Sign-in is a six digit code emailed through Resend (15 minutes, 5 attempts, 3 codes per address per hour); a session cookie then lasts a year. Tables in D1: `members`, `badges` (steering / representative, set by hand with `wrangler d1 execute`), `login_codes`, `sessions`; registering can also add the person to `signups` (general list) and set its `volunteer` flag. The registry is rendered only for signed-in members with a profile; emails show only when the member allows it or the viewer is steering committee; steering members can remove a profile. Schema in `schema.sql`.

Contact form: `functions/api/contact.js` emails the message to the community inbox through Resend (Pages secret `RESEND_API_KEY`, sender no-reply@gpsorgs.com, topic in the subject). Nothing is stored.

Join form: `functions/api/join.js` stores each signup in the Cloudflare D1 database `gpsorgs-signups` (table `signups`, schema in `schema.sql`). The binding comes from `wrangler.toml`; no secrets and no personal data live in this repo. The working mailing list is the CSV in the community Drive (`GPS Orgs Community/Mailing List/`); pull new signups into it with `sync-mailing-list.py` in that folder.
